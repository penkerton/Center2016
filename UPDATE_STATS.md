# Обновление данных ФХМ

Данные сайта выгружает единственный скрипт — `update_fhm_2016_stats.mjs`
(legacy-версия на PowerShell удалена). Он обращается к API Федерации хоккея
Москвы и формирует три файла, которые подключаются к `index.html`:

| Файл | Глобальный объект | Содержимое |
| --- | --- | --- |
| `all_2016_players_season5.js` | `window.playerGoalsData` | статистика игроков: `player`, `group`, `team`, `role`, `games`, `goals` |
| `all_2016_matches_season5.js` | `window.tournamentMatchesData` | матчи групп: счёт, дата, время, `groupId`, `tournamentId`, тур, статус |
| `site_data.js` | `window.siteData` | мета: время выгрузки, сезон, своя команда, группы с составами, состав команды с датами рождения |

## Идентификаторы ФХМ

Числовые идентификаторы зашиты в константы `TARGET_TOURNAMENT_GROUPS` и
`OWN_TEAM_ID_DEFAULT` в начале скрипта. Они относятся к сезону 26/27 и при смене
регламента меняются — тогда выгрузка упадёт с понятной ошибкой
(«Tournament … not found», «Group … not found»), а не запишет пустые данные.

| ID | Что это | Где используется |
| --- | --- | --- |
| `51` | турнир «2016 г.р. 26/27 (формат 4х4)» | целевой турнир |
| `312` | Группа Б этого турнира | статистика игроков и матчи |
| `315` | Группа В этого турнира — здесь играет «Центр» | статистика, матчи, таблица, матрица |
| `48` | турнир «2016 г.р. 26/27 (формат 5х5)» | целевой турнир |
| `309` | Группа А турнира 48 | статистика игроков и матчи |
| `604` | команда «Центр 2016» | своя команда: состав, дни рождения, «Матчи», герой |
| `5` | номер сезона в API (`--seasonId`) | все запросы |

Группа, в состав которой входит команда `604`, автоматически помечается в
`siteData.competitions` флагом `own: true` — страница берёт из неё турнирную
таблицу, матрицу и подписи сезона.

## Запуск

```powershell
node .\update_fhm_2016_stats.mjs
```

Пример с параметрами:

```powershell
node .\update_fhm_2016_stats.mjs --seasonId 5 --delayMs 120 --ownTeamId 604

node .\update_fhm_2016_stats.mjs --outputJs all_2016_players_season5.js --outputMatchesJs all_2016_matches_season5.js --outputMetaJs site_data.js
```

Все параметры: `--seasonId`, `--delayMs`, `--ownTeamId`, `--outputJs`,
`--outputMatchesJs`, `--outputMetaJs`, `--help`.

## Что делает скрипт

1. Забирает турниры сезона и находит целевые турниры `51` и `48`.
2. Для каждого берёт текущий этап и целевые группы, затем список команд группы.
3. Для каждой команды запрашивает состав и статистику игроков (амплуа, игры, голы).
4. По каждому туру каждой группы запрашивает матчи и приводит даты к формату
   `ГГГГ-ММ-ДД` + время; даты берутся из названия турнира (`26/27`).
5. Формирует состав своей команды с датами рождения и номерами.
6. Сортирует игроков: голы (убывание) → игры (убывание) → имя.
7. Записывает файлы.

## Поведение при повторном запуске

Файлы перезаписываются только если содержимое изменилось. Метка `generatedAt`
обновляется вместе с данными: если API отдал те же цифры, ни один файл не
тронется, а в логе будет `Changes: players=no, matches=no, meta=no`. Благодаря
этому GitHub Actions не создаёт коммиты при каждом запуске по расписанию.

## Защита и валидация

- Проверяются значения аргументов и путь вывода (запись только внутри рабочей
  директории, только в `.js`).
- Пустой состав любой команды и пустой состав «Центра» — ошибка, а не тихая
  запись неполных данных.
- Перед записью игроки проходят фильтр некорректных строк; запись выполняется
  только если валидных строк достаточно (`MIN_VALID_ROWS`, `MIN_VALID_RATIO`).
- Название турнира обязано содержать сезон вида `26/27`, иначе скрипт падает —
  молчаливая подстановка года исключена.
- Запросы идут с таймаутом и тремя попытками; между командами пауза `--delayMs`.

## Что проверять после запуска

1. В консоли: число команд и пустых составов, строк игроков, матчей, строк
   состава, список групп и время выгрузки, строка `Changes: …`.
2. `npm test` — контракт данных (поля, амплитуда значений, сходимость таблицы
   с матчами).
3. После перезагрузки страницы: таблица, плитки обзора, ближайший матч, матрица,
   статистика с амплуа и дни рождения заполнены, дата «Данные за …» совпадает
   со временем выгрузки.

## Если API временно недоступен

- Повторите запуск через 1–2 минуты.
- Увеличьте паузу между запросами: `node .\update_fhm_2016_stats.mjs --delayMs 250`.
- При сбое файлы не перезаписываются, поэтому на сайте остаются прежние данные.
