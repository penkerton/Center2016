# Архитектура

## Слои

```
                    fhmoscow.com

                 └───────┬────────┘
                 ┌───────▼────────┐
                 │  api.py        │  справочники и матчи → NormalizedGame
                 └───────┬────────┘
        ┌────────────────┼─────────────────┐
        ▼                ▼                 ▼
  collect.py        protocols.py      coverage.py
  (SQLite upsert)   (HTML → события)  (отчёт покрытия)
        │                │
        └────────┬───────┘
                 ▼
            data/fhm.db
                 │
     ┌───────────┼────────────┬──────────────┐
     ▼           ▼            ▼              ▼
 engine.py   features.py   backtest.py    predict.py
 (Elo,       (признаки     (walk-forward, (прогноз,
  Пуассон,    без утечки)   метрики)       хеш, файл)
```

## Модули

| Модуль | Ответственность |
|---|---|
| `config.py` | пути, целевые сезоны/турниры, параметры моделей, контрольный матч |
| `http.py` | `FhmHttp`: пауза ≥1,2 с, адаптивное увеличение после 429, 5 повторов, gzip-кеш ответов, отдача устаревшего кеша при сбое сети |
| `api.py` | эндпоинты `/api/filter/*`, `/api/game/list`, `/api/team/{id}/player`; разбор дат без года по сезону |
| `collect.py` | обход сезонов, групп, команд, матчей, заявок; upsert по официальным ID; журнал `collection_runs` и `data_quality_issues` |
| `protocols.py` | HTML страницы матча: счёт, периоды, голы с авторами; `match_periods`, `match_events`, `player_match_statistics` |
| `engine.py` | `EloEngine`, `FormTracker`, `PoissonModel`, `PlayerStrength` |
| `features.py` | один хронологический проход: признаки до обновления состояния |
| `models.py` | softmax-регрессия на numpy, метрики, калибровка, bootstrap |
| `backtest.py` | walk-forward по всем матчам, сравнение моделей, отчёты, версия модели |
| `predict.py` | прогноз матча, объяснение, отсечка, хеш признаков, сохранение и сверка |
| `projections.py` | прогноз турнирной таблицы: ожидаемые очки и разница шайб по оставшимся матчам |
| `export_site.py` | выгрузка данных и коэффициентов для статической страницы (`site/data.js`) |
| `bridge.py` | локальный сервер: статика + API обновления с паролем |
| `coverage.py` | отчёт покрытия `reports/coverage.{json,md}` |
| `quality.py` | дубли, пропуски, аномалии |
| `repository.py` | запросы для интерфейса |
| `export.py` | CSV/Excel, резервная копия через SQLite backup API |

## Поток данных

1. `collect` получает список сезонов и целевые турниры.
2. Для каждого этапа и группы скачиваются команды и матчи (по 50 на страницу).
3. Названия команд сопоставляются с ID внутри группы; матч с неизвестной командой
   не теряется молча — пишется замечание в `data_quality_issues`.
4. Заявки игроков скачиваются один раз на пару (команда, сезон) для сезонов
   2025/2026 и 2026/2027.
5. `player_team_history` пересобирается из сезонных агрегатов.
6. `backtest`/`predict` читают только БД, поэтому работают офлайн.

## Обновление без дублей

- Первичные ключи — официальные ID ФХМ (`matches.id`, `players.id`, ...).
- `db.upsert` делает `INSERT ... ON CONFLICT DO UPDATE`, поэтому повторный
  запуск обновляет счёт и даты, но не создаёт копий.
- API-ответы кешируются на 6 часов, HTML — на сутки; `--refresh` игнорирует кеш.
- При недоступности сайта клиент возвращает устаревший кеш и пишет об этом в лог.

## Интерфейс

`app.py` — один файл Streamlit с пятью разделами: «Прогноз», «Игроки»,
«Сравнение команд», «Качество модели», «Данные». Кнопки управления вызывают те
же функции, что и CLI, поэтому поведение совпадает.

## Статическая страница

`predictor/index.html` + `site/` — отдельная страница для GitHub Pages:

- `site/data.js` — снимок базы и коэффициенты модели, генерируется `export_site.py`;
- `site/model.js` — Elo, Пуассон, логистика и ансамбль на JavaScript;
- `site/app.js` — разделы «Прогноз», «Таблица», «Игроки», «Сравнение», «Качество», «Данные»;
- `site/style.css` — оформление, не зависит от стилей основного сайта.

Страница не linked с основным сайтом и помечена `noindex`. На GitHub Pages она
работает только на чтение; кнопки обновления обращаются к `bridge.py` на
`http://127.0.0.1:8765/`, который проверяет пароль `refresh` и запускает
`collect`/`backtest` + `export-site`. Ручной цикл публикации — `python main.py
publish [--push]` или `publish.bat`.

## Тесты

`tests/` использует стандартный `unittest` (без pytest):

- `test_parsing.py` — даты, форматы, разбор протокола;
- `test_db.py` — схема и идемпотентность upsert;
- `test_models.py` — Elo, Пуассон, softmax, метрики;
- `test_no_leakage.py` — признаки не меняются от будущих матчей.

Запуск: `python -m unittest discover -s tests -v`.

## Расширение

- Новый сезон: добавить ID турниров в `config.TARGET_TOURNAMENTS`.
- Новая модель: реализовать `predict()` и добавить имя в `MODEL_NAMES` и
  `ENSEMBLE_WEIGHTS`, затем пересчитать backtest.
- Построчные составы: потребуется headless-браузер или реверс JS-модуля
  `game-team-block-render`; интерфейс БД уже готов (`player_match_statistics.participated`).
