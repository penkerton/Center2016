# Источники данных

## Основной источник

`https://www.fhmoscow.com` — официальный сайт Федерации хоккея Москвы.
Страницы турниров, матчей, команд и игроков отдаются сервером (SSR), а
справочники и списки матчей подгружаются через публичный JSON API, который
использует сам сайт.

## Как устроен сайт

- **HTML страницы матча** (`/game/{id}`) содержит счёт, счёт по периодам,
  события (голы с автором, номером и временем), тренерский штаб, таблицу,
  очные встречи и последние матчи. Это основной источник протоколов.
- **JSON API** (`/api/...`) отдаёт сезоны, турниры, этапы, группы, команды,
  туры, матчи и заявки игроков.
- **Построчные составы** на странице матча подгружаются JS-модулем
  `game-team-block-render` и в HTML отсутствуют.
- SPA-переходы не нужны: все нужные данные доступны либо в JSON, либо в
  серверном HTML.

### Используемые эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/filter/season` | список сезонов (2–5) |
| POST | `/api/filter/tournament` | турниры сезона |
| POST | `/api/filter/stage` | этапы турнира |
| POST | `/api/filter/group` | группы этапа |
| POST | `/api/filter/team` | команды группы |
| POST | `/api/filter/tour` | туры группы |
| POST | `/api/game/list` | матчи, `limit` ≤ 50, `offset` |
| GET | `/api/team/{id}/player?season=N` | заявка и сезонная статистика |

Пример запроса:

```json
POST /api/game/list
{"season": 5, "tournament": 51, "stage": 63, "group": 315, "limit": 50, "offset": 0}
```

### Ограничения и особенности

1. **robots.txt** закрывает `/api` для краулеров (`Disallow: /api`). Проект
   использует API как клиент сайта: те же запросы, что делает браузер, без
   обхода авторизации и защиты. Коллектор держит паузу не меньше 1,2 с,
   увеличивает её после ответа 429 и кеширует ответы. Если владелец сайта
   закроет API, сбор остановится, но уже собранные данные и прогнозы останутся
   работоспособными. HTML-страницы матчей robots.txt разрешает — они
   используются для протоколов.
2. **429 Too Many Requests.** Сайт ограничивает частоту. Клиент делает до пяти
   повторов с экспоненциальной задержкой, увеличивает общий интервал до 12 с и
   при сбое отдаёт устаревший кеш.
3. **`limit` не больше 50.** При 100 сервер отвечает HTTP 400. Страницы
   запрашиваются по 50 матчей.
4. **Дата без года.** `displayDate` часто выглядит как «31 октября, суббота |
   09:45» — без года. Год восстанавливается по сезону: июль–декабрь — первый
   год сезона, январь–июнь — второй. Ошибка в этой логике однажды дала даты
   `2020-01-06`; после исправления проверка `date < 2024-06-01` даёт 0 строк.
5. **Нет ID команд в списке матчей.** `/api/game/list` отдаёт только названия.
   Команды сопоставляются по названию внутри группы; несовпадения пишутся в
   `data_quality_issues`.
6. **Дубли названий.** В разных группах и сезонах есть одинаковые названия,
   поэтому сопоставление делается в пределах группы, а не глобально.

## Что собрано (на 2026-11-01)

- 2 914 матчей (2 536 сыграно), 8 турниров, 90 групп, 263 команды.
- 3 299 игроков, 6 841 строка заявок, у всех игроков есть дата рождения.
- 31 событие и 3 периода — только для контрольного матча 22449; полный разбор
  протоколов запускается отдельной командой `protocols` и не выполнялся для
  всех матчей, чтобы не создавать лишнюю нагрузку.

Актуальная таблица покрытия — `reports/coverage.md`, генерируется
`python main.py report`.

## Чего на сайте нет

- Построчных составов в HTML (только через JS).
- Надёжных передач: `totalAssists` в заявках почти всегда 0.
- Вратарских сейвов, бросков, времени на льду.
- Официальных уведомлений о переходах: только факт появления в заявке другой
  команды в другом сезоне.
- Публичных PDF-протоколов, которые можно было бы использовать вместо HTML.

## Персональные данные

Собираются только спортивные сведения: имя, год рождения, амплуа, номер,
игровая статистика. Контакты, адреса, фотографии и иные личные данные не
запрашиваются и не хранятся. Интерфейс предназначен для локального
использования; рабочие данные исключены из публичного репозитория.
