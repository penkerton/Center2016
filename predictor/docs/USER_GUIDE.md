# Руководство пользователя

## Установка

Нужен Windows и Python 3.12+ (проверено на 3.14). Node.js не требуется.

```powershell
cd Other\center\predictor
python -m pip install -r requirements.txt
```

Зависимости: `requests`, `lxml`, `numpy`, `pandas`, `openpyxl`, `streamlit`.

## Первый запуск

```powershell
python main.py collect
```

Сбор занимает 10–20 минут: сайт ограничивает частоту, поэтому запросы идут с
паузой. Прогресс печатается в консоль. Прерывание не опасно: повторный запуск
продолжит с кеша и обновит существующие записи.

Затем проще всего запустить `start.bat` двойным щелчком — он откроет интерфейс
в браузере. Из PowerShell:

```powershell
python main.py backtest
.\start.bat
```

Интерфейс откроется на `http://localhost:8501`.

> Если PowerShell пишет, что `run_ui.ps1` «не подписан» и не запускается, это
> политика выполнения скриптов. Используйте `start.bat` (обычный bat-файл,
> подпись не нужна) или `powershell -ExecutionPolicy Bypass -File .\run_ui.ps1`.

## Интерфейс

### Прогноз

1. Выберите турнир (например, «2026/2027 · 2016 г.р. 26/27 (формат 4х4)»).
2. Выберите матч. По умолчанию показаны **предстоящие** матчи, ближайшие сверху;
   переключатель «Все» показывает и прошедшие игры.
3. Нажмите «Рассчитать прогноз».

Показываются:

- вероятность победы каждой команды и ничьей;
- ожидаемый исход и уверенность;
- сравнение пяти моделей;
- список факторов (Elo, ожидаемые голы, форма, состав);
- дата отсечки и хеш признаков.

**Ручная правка состава.** Раскройте «Ручная корректировка состава», отметьте
игроков, которые точно не играют, и нажмите «Рассчитать прогноз» снова.
Появится изменение вероятности в процентных пунктах.

Если матч уже сыгран, показывается фактический счёт и совпал ли прогноз. Кнопка
«Сохранить прогноз в неизменяемый файл» создаёт `predictions/match_{id}.json`;
повторно перезаписать его нельзя.

### Таблица

«Прогноз турнирной таблицы»: текущие очки плюс ожидаемые очки за все
предстоящие матчи группы (2 за победу, 1 за ничью). Показывает изменение места,
ожидаемую разницу шайб и число оставшихся игр.

### Игроки

- Выберите сезон и команду — увидите заявку с играми, голами, передачами,
  очками, штрафом и долей участия.
- Выберите игрока — появится карточка, история по сезонам и переходы между
  командами.

### Сравнение команд

Рейтинги Elo, последние 5 матчей каждой команды и очные встречи.

### Качество модели

Таблица моделей (accuracy, Brier, log loss, интервалы), калибровка, точность по
срезам. Данные берутся из `reports/backtest.json`.

### Данные

- Введите пароль `refresh` — только после этого разблокируются кнопки сбора
  статистики и пересчёта модели.
- «Обновить статистику ФХМ» — запускает `collect`.
- «Пересчитать backtest» — обновляет отчёт.
- «Проверить качество данных» — дубли, пропуски, аномалии.
- «Экспортировать базу» — CSV и Excel в `data/exports/`.
- «Создать резервную копию» — копия базы в `backups/`.
- Ниже — журнал запусков и последние замечания.

## Страница на сайте

Отдельная страница `predictor/` работает без Python на GitHub Pages:
`https://penkerton.github.io/Center2016/predictor/`. На неё нет ссылок с
основного сайта, она закрыта от индексации (`noindex`).

- «Прогноз» — вероятности для будущих матчей и ручная правка состава;
- «Таблица» — прогноз турнирной таблицы по всем оставшимся играм группы;
- «Игроки», «Сравнение», «Качество модели» — те же данные, что в Streamlit;
- «Данные» — снимок базы и кнопки обновления.

Обновление страницы: `python main.py export-site`, затем закоммитить
`site/data.js`. Локально с работающими кнопками: `bridge.bat` →
`http://127.0.0.1:8765/`, пароль `refresh`. На GitHub Pages кнопки обновления
недоступны, потому что там нет серверной части.

## Публикация на сайт

Обновление и расчёт модели выполняются вручную на локальном компьютере:

```powershell
.\publish.bat
```

Скрипт спрашивает подтверждение, затем выполняет `collect` → `backtest` →
`export-site` → `git commit` → `git push`. Через 1–2 минуты GitHub Actions
пересоберёт `https://penkerton.github.io/Center2016/predictor/`.

Без публикации: `python main.py publish` (только локальный коммит) или
`update.bat` (только сбор данных). Кнопки на самой странице работают лишь при
запущенном `bridge.bat` и пароле `refresh`; на Pages их нет.

## Команды

```powershell
python main.py status                 # что уже собрано
python main.py collect --season 5     # только текущий сезон
python main.py backtest               # пересчитать качество
python main.py predict --match 22449  # прогноз в консоль
python main.py predict --match 22449 --cutoff "2026-10-31T09:45:00+03:00" --save --immutable
python main.py verify --match 22449   # сверка с фактом
python main.py protocols --season 5 --limit 20
python main.py report                 # покрытие
python main.py check                  # качество данных
python main.py export
python main.py backup
```

## Обновление после новых матчей

```powershell
python main.py collect
python main.py backtest
```

`collect` скачивает только изменившееся: справочники и заявки кешируются,
матчи обновляются по ID. Если сайт недоступен, база остаётся рабочей, а
интерфейс показывает дату последней успешной загрузки.

Периодический запуск через Планировщик заданий Windows можно настроить вручную
(проект не создаёт задание без разрешения):

```
Программа: python.exe
Аргументы: main.py collect
Рабочая папка: ...\Other\center\predictor
```

## Резервное копирование и откат

- Копия базы: `python main.py backup` → `backups/fhm-YYYYMMDD-HHMM.db`.
- Откат: закройте интерфейс, замените `data/fhm.db` нужной копией.
- Версии моделей: `model_versions` хранит параметры и метрики последнего
  успешного backtest; прежняя версия остаётся в таблице.

## Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `run_ui.ps1` «не подписан» | политика выполнения PowerShell | запустить `start.bat` или `powershell -ExecutionPolicy Bypass -File .\run_ui.ps1` |
| Долгие паузы, в логе «429» | сайт ограничивает частоту | подождать, не запускать параллельно; кеш сохранит прогресс |
| «Не удалось рассчитать прогноз: Недостаточно матчей» | мало данных в базе | выполнить `collect` |
| Порт 8501 занят | другой Streamlit | `streamlit run app.py --server.port 8502` |
| Пустые передачи | источник их не отдаёт | ограничение, не ошибка |
| Дата матча неверная | у сайта нет года в дате | сообщить, год выводится из сезона |

## Приватность

Все данные локальны. В публичный репозиторий не попадают `data/`, `backups/`,
`predictions/`, `reports/` — они в `.gitignore`.
