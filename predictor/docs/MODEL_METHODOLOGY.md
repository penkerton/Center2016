# Методика моделей

## Защита от утечки будущего

Для каждого матча признаки считаются по состоянию **до** его начала:

1. Матчи сортируются по `(дата, время, id)`.
2. `build_observations` идёт по списку: сначала `state.features(match)`, затем
   `state.observe(match)` (обновление Elo, формы, Пуассона).
3. Логистическая регрессия переобучается только на строках до текущего матча
   (каждые 30 матчей).
4. Пуассон пересчитывается только по прошлым матчам (каждые 40).
5. `test_no_leakage` проверяет, что признаки префикса не меняются, если добавить
   будущие матчи.

Для контрольного матча используется отсечка `2026-10-31 09:45` (МСК) и хеш
признаков; всё, что стало известно позже, в прогноз не попадает.

## Модель 1. Elo

- Старт 1500, K = 24, домашнее преимущество +60.
- Ожидаемая победа: `1 / (1 + 10^(-(R_home - R_away + 60) / 400))`.
- Поправка на крупный счёт: `K × (1 + 0.35 × ln(1 + |разница|))`.
- Между сезонами рейтинг возвращается к 1500 на 1/3.
- Ничья: `draw_rate × (1 - 2|p - 0.5|)`, где `draw_rate` — сглаженная доля
  ничьих в прошлом.

## Модель 2. Пуассон

Результативность:

```
λ_хозяев = avg × attack_home × defense_away × home_factor
λ_гостей  = avg × attack_away × defense_home
```

- `attack` и `defense` оцениваются итерациями (8 проходов) по прошлым матчам с
  весом `exp(-ln2 × давность / 240 дней)`;
- приор 6 матчей тянет оценки к среднему;
- `home_factor` оценивается по соотношению голов хозяев и гостей (0,8–1,25);
- вероятности считаются по матрице счетов 0…15.

Проверка сверхдисперсии на 4 844 наблюдениях (голы одной команды в матче):
среднее **9,04**, дисперсия **84,9**, отношение **9,39**. Это выраженная
сверхдисперсия: Пуассон недооценивает редкие крупные счета (36:0, 0:28).
Negative Binomial не реализован; распределение Пуассона используется как
приближение, потому что по итоговой точности исхода оно всё равно обгоняет Elo,
но крайние вероятности могут быть смещены.

Градиентный бустинг (CatBoost/LightGBM) не проверялся: эти зависимости не
установлены, а логистическая регрессия на 16 признаках уже дала лучший log loss
среди реализованных моделей. Добавление бустинга — направление развития, а не
скрытая часть системы.

## Признаки

16 признаков: `elo_diff`, `elo_home`, `elo_away`, `form_ppg_diff`,
`form_gf_diff`, `form_ga_diff`, `rest_diff`, `experience_diff`,
`poisson_log_ratio`, `player_diff`, `is_4x4`, `is_5x5`, `is_2016`,
`is_group_a`, `is_group_b`, `is_group_v`.

- форма — последние 5 матчей (2 очка за победу, 1 за ничью);
- `rest_diff` — разница дней отдыха (0…60);
- `experience_diff` — логарифм числа сыгранных матчей;
- `player_diff` — разница силы составов по прошлым сезонам.

## Модель 3. Логистическая регрессия

- Мультиномиальный softmax на numpy, 3 класса (победа хозяев / ничья / победа
  гостей).
- Стандартизация признаков по обучающей выборке.
- L2 = 0,05, Adam, 500 эпох, learning rate 0,08.
- Переобучение в walk-forward каждые 30 матчей, минимум 60 строк.
- Seed 20261031.

## Модель 4. Player-Aware

Основа — Elo, но к разнице рейтингов добавляется бонус за состав:

```
bonus = clip(220 × (strength_home - strength_away), -120, +120)
strength = средневзвешенный impact топ-8 игроков по прошлым сезонам
```

Модель обучается без текущего сезона: для матчей 2026/2027 используются заявки и
статистика 2025/2026. Исключение игрока в интерфейсе пересчитывает `strength`
без него и меняет вероятность.

Результат: на 2 302 матчах модель практически не отличается от Elo
(accuracy 0,691 против 0,688), поэтому её вес в ансамбле равен 0. Это
зафиксировано как отрицательный результат.

## Ансамбль

Веса подбирались перебором с шагом 0,1 на **первых 70%** проверочных матчей по
log loss, затем проверены на отложенных 30%:

- итог: `0,6 × логистическая регрессия + 0,4 × Пуассон`;
- Elo и Player-Aware получили вес 0;
- на отложенных 30%: accuracy 0,770, Brier 0,336, log loss 0,583.

Смешивание с базовыми частотами (0,02–0,1) не улучшило log loss, поэтому не
применяется.

## Ничьи

Ничьи в данных есть (72 из 2 302), но редки. Все модели возвращают три
вероятности; ничья не превращается в победу одной из команд. При выводе
победитель определяется по максимальной вероятности, а ничья отображается
отдельно.

## Метрики

- **Accuracy** — доля матчей, где исход с максимальной вероятностью совпал.
- **Brier** — средняя сумма квадратов отклонений по трём классам.
- **Log loss** — `-mean(ln p(факт))`; меньше — лучше.
- **Калибровка** — 10 бинов по прогнозу победы хозяев: средний прогноз против
  фактической частоты.
- **95% интервал** — percentile bootstrap, 300–500 повторов.

## Уверенность

В интерфейсе «уверенность» — эвристика по данным, а не вероятность:
«высокая» при ≥10 матчах у обеих команд и ≥20 строках статистики, «средняя»
при ≥5, иначе «низкая». Она не заменяет интервалы из backtest.

## Воспроизводимость

- Все вычисления — из локальной SQLite.
- Версии зависимостей зафиксированы в `requirements.txt`.
- Seed — 20261031.
- Каждый прогноз хранит отсечку и SHA-256 хеш признаков.
