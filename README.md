# Сайт хоккейной команды «Центр» (2016 г.р.)

Одностраничный сайт команды: обзор сезона, турнирная таблица и матрица очных
встреч, матчи с обратным отсчётом и добавлением в календарь, статистика игроков
турниров и дни рождения команды.

Никаких данных внутри разметки нет: таблица, плитки обзора, ближайший матч,
матрица и дни рождения собираются в браузере из файлов, которые выгружает
скрипт с сайта Федерации хоккея Москвы. Выгрузка запускается автоматически
каждые 3 часа.

## Структура

```
index.html                     разметка и подключение ресурсов
css/                           стили по слоям:
  tokens.css                     темы и переменные
  base.css                       база, фон, типографика
  layout.css                     шапка, навигация, прогресс прокрутки
  components.css                 карточки, кнопки, таблицы, анимация появления
  sections.css                   секции страницы и их элементы
  responsive.css                 медиазапросы, reduced-motion, печать
js/
  main.js                        точка входа: порядок инициализации
  lib/                           переиспользуемые модули без DOM-состояния
    data.js                        чтение и проверка выгруженных данных
    format.js                      форматирование, даты и время по Москве
    standings.js                   расчёт турнирной таблицы
    h2h.js                         расчёт матрицы очных встреч
    ics.js                         файл календаря (.ics)
    scheduler.js                   единый таймер приложения
    tabs.js                        доступные вкладки (WAI-ARIA)
    dom.js                         мелкие помощники
  modules/                       блоки страницы
    theme.js, header.js, motion.js, meta.js, dashboard.js,
    standings-table.js, h2h-matrix.js, matches.js, stats.js, birthdays.js
scripts/serve.mjs              локальный статический сервер
tests/                         проверки (node:test, без зависимостей)
update_fhm_2016_stats.mjs      выгрузка данных с ФХМ
all_2016_players_season5.js    ← window.playerGoalsData (генерируется)
all_2016_matches_season5.js    ← window.tournamentMatchesData (генерируется)
site_data.js                   ← window.siteData (генерируется)
```

## Локальный запуск

Страница использует ES-модули, поэтому по `file://` она не откроется — нужен
локальный сервер (зависимостей нет, только Node.js 20+):

```powershell
npm start            # http://127.0.0.1:4173/
```

## Обновление данных

```powershell
npm run update       # нужен доступ в интернет
```

Скрипт формирует три файла данных и **не перезаписывает их, если содержимое не
изменилось** (метка времени выгрузки тогда тоже остаётся прежней) — поэтому
регулярные запуски не создают пустых коммитов. Подробности и таблица
идентификаторов ФХМ — в [UPDATE_STATS.md](UPDATE_STATS.md).

В GitHub Actions те же шаги выполняет [.github/workflows/update-data.yml](.github/workflows/update-data.yml)
каждые 3 часа: выгрузка → проверки → коммит только при изменениях → деплой Pages.

## Проверки

```powershell
npm test             # node:test: расчёты, форматирование, .ics, контракт данных
```

Тесты без внешних зависимостей: считают турнирную таблицу, проверяют московское
время и склейку `.ics`, а также валидируют сами выгруженные файлы (поля игроков,
даты матчей, состав команды, сходимость таблицы с матчами).

## Как данные попадают на страницу

1. `update_fhm_2016_stats.mjs` обращается к API ФХМ (`/api/filter/*`, `/api/game/list`,
   `/api/team/{id}/player`), проверяет и нормализует ответы.
2. Формируются три JS-файла с глобальными объектами (`window.siteData`,
   `window.playerGoalsData`, `window.tournamentMatchesData`).
3. `js/lib/data.js` превращает их в модель страницы, `js/main.js` раздаёт её
   модулям, а те рисуют разметку.

Имена команд нормализуются только на шаге выгрузки — страница работает с уже
готовыми названиями без суффикса «2016».

## Время и часовые пояса

Все даты и время трактуются как московские (`Europe/Moscow`), независимо от
часового пояса посетителя: и обратный отсчёт до матча, и разделение матчей на
предстоящие и прошедшие, и «сегодня/через N дней» в днях рождения. Файл `.ics`
содержит время в UTC, поэтому в календаре телефона матч встаёт на правильный час
в любом поясе.

## Деплой

GitHub Pages публикует содержимое репозитория как статику. Деплой выполняется
из двух мест: `pages.yml` — при обычном пуше в `main`, `update-data.yml` — после
автоматического обновления данных (пуш от `GITHUB_TOKEN` не запускает другие
workflow, поэтому деплой там продублирован осознанно). Оба workflow используют
общую группу `concurrency: pages`, чтобы деплои не накладывались.

## Что проверить после обновления данных

1. `npm test` — контракт данных и расчёты.
2. `npm start` и страница: таблица заполнена, лидер по очкам сверху, в матрице
   есть счёта сыгранных матчей, в «Прошедших» нет цифр счёта в строке команд
   (счёт вынесен в отдельный контрол), дни рождения совпадают с составом.
3. Дата «Данные за …» в шапке обзора и подвале соответствует времени выгрузки.
